# 青禾优选会员运营业务说明

版本：qinghe-business-v1，2026-11-17。课程模拟客户的学习草稿，由Codex依据本人三场正式访谈整理、核对，供用户审阅及本地AI问答试验；不表示用户已采用方案、客户事实已全面验证或真实业务已获批准。

## 1. 本轮回答什么问题

解释会员运营任务如何从运营安排走向门店执行、怎样反馈，以及回访名单需要哪些业务定义和核查条件。范围包含会员类别、任务与活动、门店执行、信息依据和角色分工。

本说明不计算实际回访名单、复购率或收益，不接客户系统，不执行联系、发券、打标签或修改考核。说明业务含义不会自动获得计算数据和执行权限。

| 会员标签 | 系统中存在的会员描述项，具体含义、用途、填写人、填写环节和更新方式未核实 | 不能直接作为统一购买意向或资格，不据此自动决定谁该联系。MSG-05872、05887 |

| 效果依据 | 判断会员是否变化、复购是否改善所需的核实材料；与安排落实、员工体验分开 | 当前没有可确认效果统计、计算口径与归因证据。MSG-05859、05891 |

## 3. 从安排到反馈的通常流程

1. 小林查看未完成运营任务和反馈，明确本次面向什么人、准备做什么。名单筛选及分组细则本次未展开（MSG-05849、05853）。
2. 小林与同事确认线上或门店执行安排。陈姐在门店侧核对面向对象、参与门店和要做的事，再说明任务、确认人员安排（MSG-05849、05881）。
3. 门店按活动要求做权益说明、接待咨询、配合注册及活动执行；具体人员分工随活动确认（MSG-05881）。不把这些通常活动动作当作某次回访已经发生。
4. 活动说明和现场理解不一致时，陈姐找小林核对，问清再执行。线上可见只是信息出现，不能代替活动适用范围（MSG-05885）。
5. 执行中收集问题和反馈，结束后整理执行情况回给运营小林；小林自述以个人Excel记录进度、问题和反馈，缺反馈会反复跟进（MSG-05857、05889）。
6. 对是否带来会员变化或复购改善，另查效果依据。安排落实、记录整理齐全不自动等于经营改善（MSG-05859、05891）。

这是两位角色自述的通常流程，经AI对照整理；未取得某次活动从起点到收尾的完整原始记录，也不是已确认的全公司制度。

## 4. 条件、规则与权限边界

- **人群条件**：区分付费卡、免费注册、系统全量、活跃等含义；120万仅为老周的系统全量陈述。80万在本轮由访谈者转述沈总说法，老周未确认。不得相减声称40万流失，也不能按两类会员简单相加。
- **标签条件**：填报与含义未核实，不能把有标签等同有可靠意向依据；目前同样不能断言标签乱填或全部不可用。
- **数据条件**：查不到订单时须核对线上／门店渠道以及所选门店与时段覆盖；具体系统位置、关联方式和区分能力尚未取得，不断言已经具备或完全不具备。
- **活动适用条件**：按活动说明核对适用范围、参与门店、具体动作和安排；歧义由陈姐找小林核对（MSG-05885）。
- **门店接受条件**：陈姐要求活动清楚、少反复确认、不冲击门店考核。要求不清或影响考核会要求澄清、调整；这是其经验判断和接受条件，不是已验证的业绩损失或正式制度（MSG-05891、05893）。
- **取数条件**：老周要求明确对象、范围、用途、所需材料、配合人和责任；安全或责任不清可暂缓技术接入。本次访谈没有批准正式数据权限（MSG-05878）。
- **现场与业务配合**：陈姐愿协调人员和现场，活动范围和工作量找小林，原始数据及完整性指向老周。她所说“老周点头”不证明老周拥有正式数据授权权（MSG-05897对照05878）。
- **试点状态**：访谈者提出一个门店、约定时段、最小脱敏样本的建议，仅用于询问前提；老周明确未批准，不是已确定试点（MSG-05877、05878）。

## 5. 待核的不同说法与未知

| 事项 | 各方说法或未知 | 可能的影响与核查办法 |
|---|---|---|
| 谁确认门店时段完整性 | 老周说找陈姐（05878）；陈姐说自己只能确认经手活动和反馈，系统完整性找老周（05897） | 可能分别指现场业务覆盖和系统数据覆盖，尚不能判定推责或自相矛盾。选同一门店、时段、记录类型，明确二人各自核对什么、依据是什么、谁汇总结论；该分工建议未获双方确认 |
| 人数统计 | 全量120万是老周陈述，80万活跃算法未知；两类会员是否重叠未知 | 运营和IT共同核对统计范围、时间及说明，取得报表后才能比数；不能据差额决定联系名单 |
| 标签 | 老周与陈姐均无法确认填写环节，陈姐把系统定义指向老周 | 共同未知不算冲突；需定义说明、填写样本和实际填报者 |
| 执行反馈 | 门店给运营反馈的关系有双方说法；具体是否区分联系／回应／购买未知 | 核对同一次任务的实际反馈及小林工作记录，不能自动建立已存在的状态字段 |
| 旧系统 | 小林称界面增加三步并用Excel绕开（05861）；老周没有具体页面资料（05876）；陈姐没有使用清单（05895） | 小林反馈未被独立验证；不能据此裁定整体失败原因或决定重做 |
| 效果及考核 | 复购算法、提升幅度、效果统计、门店考核具体口径均未取得 | 向业务及制度负责人取得说明和样本，不推断负责人最终审批权，不承诺收益 |

## 6. 候选动作与为何这样建模

候选方向是协助整理活动说明、列出适用门店与动作及问题联系人、整理反馈和待确认信息。依据是小林的整理与跟进负担（05851、05857）及陈姐对要求清楚和减少反复沟通的诉求（05893、05895）。这些尚不是已确认需求、系统已有功能或已执行动作。

我们把“任务、执行反馈、效果依据”分开，是为了避免把完成任务当作复购改善；把“活动适用范围、门店安排”单列，是为了让建议能接上实际执行；把“数据覆盖和口径”单列，是为了避免错判名单。这些是当前用途下的建模选择，未来可按新证据修订。

验证应分别观察：资料能否支持名单；门店是否理解并能执行；反馈能否证明执行；经营效果是否改善。不能用前一项通过替代后一项，也不能用回答更流畅证明业务有效。
